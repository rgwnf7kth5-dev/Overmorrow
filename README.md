# The Overmorrow

*Tomorrow happens. Overmorrow reports it. You read it today.*

A newspaper written two days ahead, in English (default) and Czech (/cs/), with a one-page A4 print edition of every issue (/print/, /edition/DATE/print/). Each edition reports the scheduled and expected events of the next day as if they had happened, and attaches a probability to every forecast. After the events, each forecast is checked and scored, and the result is stamped onto the archived edition.

- **How it works:** [METHODOLOGY.md](METHODOLOGY.md)
- **Evening desk (agenda, dossiers, forecast board):** [pipeline/PLANNER.md](pipeline/PLANNER.md)
- **Producing an edition:** [pipeline/EDITOR.md](pipeline/EDITOR.md)

## Repository layout

| Path | What it holds |
|---|---|
| `data/editions/YYYY-MM-DD.json` | One file per edition, named by its date. Never edited after publication. |
| `data/updates/YYYY-MM-DD.json` | The afternoon update of that edition: revised probabilities and added stories. |
| `data/resolutions/YYYY-MM-DD.json` | Results for that edition's claims, added as they fall due. Append-only. |
| `data/corrections/YYYY-MM-DD.json` | Corrections to facts in a published edition's text, shown under the story. |
| `data/watchlist.json` | The forecast board: standing questions, their full forecast history and results. |
| `data/planning/` | The evening desk's 14-day agenda and the shortlist for the next edition. |
| `data/dossiers/YYYY-MM-DD/` | Research dossiers behind each claim of that edition. |
| `data/postmortems.md` | Reviews of confident misses and of badly designed claims. |
| `data/publisher/YYYY-MM-DD.json` | The publisher's own probabilities on that edition's claims, scored separately (METHODOLOGY 11). |
| `METHODOLOGY.cs.md` | Czech version of the methodology, shown at /cs/method/. |
| `pipeline/` | Source registry, reference classes, settings and manuals (EDITOR, PLANNER, RESOLVER, UPDATE). |
| `pipeline/reference-data/` | Base rates computed from data, rebuilt by `scripts/refdata/`, and schedule-slip rates (`schedule-slip.json`). |
| `pipeline/calibration.json` | Forecaster weights and bias correction fitted on our own record by `scripts/calibrate.mjs`. |
| `scripts/markets.mjs` | Prediction-market lookup (Polymarket, Kalshi, Manifold, Metaculus with a token). Bookmakers' odds: `scripts/refdata/models.mjs odds`. |
| `scripts/validate.mjs` | Checks all data against the rules. The Netlify build fails on any error. |
| `scripts/build.mjs` | Generates the site into `dist/`. No dependencies beyond Node 20. |
| `site/style.css` | The stylesheet. |
| `site/logo.svg`, `site/favicon.svg` | The engraved seal logo and the simplified favicon, generated by `tools/make-logo.mjs`. |

## The publisher's forecasts

To add your own figures, tell Claude (in this project) the edition date, the claim ids or headlines and your probabilities, and whether you had read the paper's figure first. They are written to `data/publisher/<edition date>.json`:

```json
{ "edition": "2026-10-26", "entries": [ { "claim": "cz-budget-second-reading", "p": 0.7, "at": "2026-10-24T07:30:00+02:00", "saw_paper": true } ] }
```

Only figures given before the events day begins count. They never change the paper.

## Local build

```
node scripts/validate.mjs
node scripts/build.mjs
npx serve dist
```

## Netlify

Connect the repository; `netlify.toml` sets the build command and the `dist` publish directory. Deploy previews for pull requests are used to review each edition before it is merged.

## Photographs (experiment)

Optional illustrative photographs per edition live in `data/images/<edition>.json` (story id → file, alt text, caption, credit, licence, Commons source; Czech `alt_cs`/`caption_cs`), with the image files in `site/photos/<edition>/` (960 px wide JPEG). Only freely licensed photos of places and objects, never people at events that have not happened yet; every photo is credited and marked as illustrative. The edition file itself is never touched; deleting the JSON removes the photos. Not used in the print edition.
